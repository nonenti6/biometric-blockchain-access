# Биометрический блокчейн — контроль доступа

Python + Tkinter + PostgreSQL. Один узел, SHA-256, дерево Меркла, формирование блоков раз в 60 секунд. Сканер **имитируется** точным сравнением тестовых байтов.

## Возможности

- Имитация сканирования тестовых отпечатков сотрудников.
- Создание транзакций только при успешном проходе.
- Автоматическое формирование блоков раз в 60 секунд при наличии ожидающих транзакций.
- Просмотр транзакций, блоков и их хэшей.
- Проверка целостности блокчейна.
- Имитация подмены данных транзакции и её хэша.
- Приостановка формирования блоков при обнаружении изменений.
- Восстановление транзакции из резервной копии.

## Установка и запуск

1. Создать базу `biometric_blockchain` в PostgreSQL.
2. В pgAdmin 4 выполнить `sql/schema.sql`, затем `sql/migration_restore.sql`.
3. Установить зависимости:

   ```bash
   pip install -r requirements.txt
   ```

4. Указать параметры подключения в `.env`:

   ```dotenv
   DATABASE_URL=postgresql://postgres:YOUR_PASSWORD@localhost:5432/biometric_blockchain
   ```

5. Запустить приложение:

   ```bash
   python main.py
   ```

## Вкладки

- **Сканер и сотрудники** — имитация проходов.
- **Транзакции** — журнал успешных проходов и статус `PENDING`.
- **Блокчейн** — список блоков и их содержимое.
- **Проверка целостности** — выявление изменённых данных и хэшей.
- **Имитация атаки** — подмена и восстановление транзакций.

## Принцип работы

Успешный проход → транзакция → блок → проверка SHA-256, дерева Меркла и связей блоков. При обнаружении нарушения новые транзакции остаются `PENDING` до восстановления целостности.

## Что именно хэшируется

- Отпечаток: SHA-256 от исходных байтов тестового шаблона.
- Транзакция: канонический JSON с полями `transaction_id`, `employee_id`, `employee_name`, `fingerprint_hash`, `passed_at`.
- Канонизация: `json.dumps(..., ensure_ascii=False, sort_keys=True, separators=(',', ':')).encode('utf-8')`; время UTC, ISO 8601 с микросекундами.
- Дерево Меркла: попарный SHA-256 от конкатенации **сырых 32-байтных хэшей**; нечётный последний элемент дублируется.
- Хэш блока: SHA-256 от канонического JSON с полями `block_id`, `created_at`, `previous_hash`, `merkle_root`, `transactions_count`.
- Генезис-блок: индекс 0, предыдущий хэш и Merkle root равны 64 нулям.

## Ограничения

Это **не защищённая распределённая система**: нет Proof of Work, независимых узлов, цифровых подписей или внешнего доверенного контрольного хэша. Злоумышленник с полным доступом к PostgreSQL способен переписать всю цепочку и пересчитать хэши. Демонстрация исходит из более узкой модели угроз: изменяется транзакция и, возможно, её хэш, но не пересчитывается вся история блоков.

Проверка транзакций не доказывает корректность исходной регистрации отпечатка. Подмена эталонного шаблона в `employees` — отдельная угроза, **не защищённая** этим прототипом. Приложение рассчитано на один запущенный экземпляр; не запускайте два экземпляра одновременно. Таймер работает только при открытом приложении и отсчитывает минуту с момента запуска.
